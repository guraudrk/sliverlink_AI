## 세션: Day 34 S3~S7 — 기관 테넌시 마이그레이션 DB 적용 + 침투 테스트

### 요청과 목표

- S2에서 승인된 마이그레이션 SQL을 Supabase DB에 실제 적용
- 적용 후 즉시 침투 테스트(PT-0~3)로 RLS 보안 검증

### 구현 및 변경 내용

**마이그레이션 내용 (docs/migration-v2-org-tenancy.sql):**

- `organizations` 테이블 신규 생성 (id, name, slug, is_demo)
- `org_members` 테이블 신규 생성 (org_id, user_id, role: admin/social_worker/field_worker)
- `parent_profiles`에 `org_id`, `assigned_user_id` 컬럼 추가
- SECURITY DEFINER 함수 4개: `is_org_member`, `is_org_admin`, `can_access_parent`, `can_access_parent_any`
- `prevent_parent_org_change` BEFORE UPDATE 트리거: org_id·owner_user_id 클라이언트 변경 차단
- 전 테이블(14개) RLS를 `owner_user_id = auth.uid() OR can_access_parent(parent_id)` 패턴으로 확장
- `social_scores` unique 제약을 `(owner_user_id, parent_id, week_start)` → `(parent_id, week_start)`으로 변경
- `create_org_with_admin` 함수: 신규 기관 생성 + 첫 admin 원자적 등록 (anon/authenticated REVOKE)

**침투 테스트 결과:**
- PT-0: anon이 organizations SELECT → 0건 ✅
- PT-1: A기관 admin이 B기관 org_members INSERT → RLS 차단 ✅
- PT-2: 기관 멤버가 parent_profiles.org_id = NULL 로 UPDATE → 트리거 차단 ✅
- PT-3: field_worker가 비배정 어르신 SELECT → 0건 ✅

### 문제와 해결 과정

**1차 실패: 42P01 — org_members 테이블 없음**

`LANGUAGE sql` 함수는 생성 시점에 참조 테이블이 존재해야 한다. `is_org_member`/`is_org_admin`이 `org_members`를 참조하는데 테이블이 함수보다 나중에 생성돼 실패.

→ 테이블 생성을 함수 생성 앞으로 이동.

**2차 실패: 42703 — parent_profiles.org_id 컬럼 없음**

`can_access_parent`가 `pp.org_id`를 참조하는데, `parent_profiles`에 컬럼 추가는 더 나중 단계였다.

`LANGUAGE sql`은 컬럼 존재도 함수 생성 시점에 검증한다는 사실을 이 과정에서 확인.

→ 함수를 두 단계로 분리. 3A: `is_org_member`/`is_org_admin` (org_members만 참조), 3B: `can_access_parent`/`can_access_parent_any` (parent_profiles 컬럼 추가 이후).

**3차 실패: 2BP01 — ROLLBACK SQL이 자동 실행됨**

SQL 파일에 Forward 마이그레이션과 ROLLBACK SQL을 같은 파일에 넣었더니 Supabase SQL Editor가 두 BEGIN...COMMIT 블록 모두 실행했다. Forward는 성공했으나 ROLLBACK 블록이 `can_access_parent_any` DROP 시도 중 의존 정책 때문에 실패.

→ Forward 마이그레이션은 이미 COMMIT 완료 상태임을 확인. ROLLBACK 섹션을 주석 처리해 재실행 방지.

**침투 테스트 환경 구성 시행착오:**

- `SET LOCAL "request.jwt.claims" = json_build_object(...)`: 문법 오류 → `set_config()` 함수로 교체
- `SET LOCAL ROLE authenticated` 후 `auth.users` 조회: permission denied → UUID를 service_role 단계에서 미리 조회, PL/pgSQL 변수로 넘기는 방식으로 해결

### 기술적 의사결정

- **함수 분리(3A/3B)**: `LANGUAGE sql` vs `LANGUAGE plpgsql`의 검증 시점 차이를 활용. `plpgsql`로 바꾸면 런타임 오류가 되므로, 의존 순서를 올바르게 지키는 `LANGUAGE sql` 방식을 유지.
- **ROLLBACK 섹션 분리**: 같은 파일에 두 트랜잭션 블록을 넣으면 자동 실행되는 문제 → 주석으로 격리. 다음부터는 ROLLBACK을 별도 파일로 관리.
- **침투 테스트 DO 블록**: `BEGIN...EXCEPTION` 패턴으로 PASS/FAIL을 SQL 내부에서 자동 판정. 예상 실패를 에러 없이 검증 가능.
