삼성 갤럭시 A34와 Android 에뮬레이터에서 앱이 스플래시 화면 이후 즉시 종료되는 크래시를 완전히 해결했다. 원인은 `expo-location` 패키지를 SDK 57용 버전(`57.0.7`)으로 잘못 설치한 것이었다. 우리 앱은 expo SDK 54를 사용하는데, 57.x 버전의 패키지 안에 사전 컴파일된 AAR 파일이 SDK 57에서 추가된 `AnyTypeCache` 클래스를 참조하고 있어 런타임에 클래스를 찾지 못하는 오류가 발생했다. ## 세션: ai-myeoneuri — `ClassNotFoundException: AnyTypeCache` 크래시 근본 원인 규명 및 수정

### 요청과 목표

### 문제와 해결 과정

**원인 특정 과정 (이전 세션에서 완료)**

1. `adb logcat`에서 `ClassNotFoundException: expo.modules.kotlin.types.AnyTypeCache` 확인
2. `expo-location`의 `expo-module.config.json`에서 `"publication"` 필드 발견 → pre-compiled AAR 사용 경로 확인
3. `expo-location/local-maven-repo/expo.modules.location-57.0.7.aar`를 JAR 해제하여 `LocationLastKnownOptions$__Pika.class` 등 Pika KSP 생성 클래스 확인
4. `dexdump -d`로 최종 APK DEX에서 `AnyTypeCache.INSTANCE.getTypesMap()` 바이트코드 참조 확인
5. `expo-modules-core 3.0.30`에는 `AnyTypeProvider`가 있고 `AnyTypeCache`가 없음 → 버전 불일치 확정

**해결 방법 선택**

- **Option A (채택): expo-location 다운그레이드** — `expo/bundledNativeModules.json`에서 SDK 54 공식 버전 `~19.0.8` 확인 후 변경
- Option B (미채택): `forceBuildFromSource` + KSP 플러그인 추가 — 소스에서 빌드 강제, 더 복잡하고 빌드 시간 증가

**expo-location 19.x 안전성 검증**

```
jar xf expo.modules.location-19.0.8.aar
jar tf classes.jar | grep -i "Pika\|AnyType"
# 결과: 출력 없음 (Pika KSP 클래스 없음)
```

- `expo-location 19.x`는 `@OptimizedRecord`/Pika KSP를 사용하지 않음 → `AnyTypeCache` 참조 없음

### 기술적 의사결정

**왜 `^57.0.7`이 설치됐는가**

`^` (caret) 지정자는 major 버전을 고정하지 않는다. expo 생태계의 패키지들은 SDK 버전과 major 버전이 일치하는 경우가 많아 (`expo SDK 54 → expo-location 19.x`, `expo SDK 57 → expo-location 57.x`), `^`를 쓰면 SDK 버전을 훌쩍 넘는 major 버전으로 업그레이드될 수 있다. expo 패키지는 반드시 `~` (tilde, 패치 범위) 또는 `expo install` 명령으로 설치해야 한다. `expo install`은 `bundledNativeModules.json`에서 SDK에 맞는 버전을 자동 선택한다.

**pre-compiled AAR 시스템의 위험성**

expo-location 57.x는 npm 패키지 안에 사전 컴파일된 AAR을 포함하고 있다. 이 AAR은 배포 시점의 expo-modules-core 버전에 맞게 컴파일됐는데, 앱이 다른 버전의 expo-modules-core를 사용하면 런타임에 클래스를 찾지 못한다. 에러 메시지가 `expo-location`이 아닌 내부 클래스명(`AnyTypeCache`)으로 나타나기 때문에 진단이 어렵다.

## 세션: S1 음성인식 — expo-speech-recognition 교체 → 커스텀 Android SpeechRecognizer

### 요청과 목표

- 이전 세션에서 `expo-speech-recognition 3.1.3`을 설치했으나 앱 시작 시 `TypeError: Cannot read property 'EventEmitter' of undefined` 크래시 발생
- 두 번의 JS 레벨 수정 시도(addListener lazy화, useMemo) 모두 실패
- 이번 목표: 근본 원인 파악 → 크래시 없는 음성인식 구현

### 문제와 해결 과정

**원인 분석**

`expo-speech-recognition 3.1.3`의 JS 빌드 파일 (`build/ExpoSpeechRecognitionModule.js`)를 확인:

```js
export const ExpoSpeechRecognitionModule = requireNativeModule("ExpoSpeechRecognition");
const stop = ExpoSpeechRecognitionModule.stop;   // ← 모듈 레벨 실행
ExpoSpeechRecognitionModule.stop = () => stop();  // ← undefined.stop() 위험
```

이 코드는 JS 번들 로드 시점에 즉시 실행된다. `requireNativeModule`이 네이티브 모듈 객체를 반환하더라도, 그 다음 줄이 모듈 레벨에서 실행되기 때문에 모듈 초기화 순서 문제가 생기거나, 반환 객체의 구조가 예상과 다르면 바로 크래시가 발생한다.

**DEX 확인**

```
grep -rl "speechrecognition" android/app/build/
# → classes2.dex 에서 발견
```

네이티브 모듈 자체는 APK DEX에 포함되어 있었다. 즉, autolinking은 정상 작동. 크래시 원인은 JS 레벨의 모듈 초기화 문제였다.

**결론: expo-speech-recognition 전면 교체**

패키지 자체의 JS 코드 구조가 문제이므로, 패키지를 완전히 제거하고 Android SpeechRecognizer를 직접 사용하는 커스텀 React Native 네이티브 모듈로 교체했다. 외부 패키지 의존성 없이 OS 내장 음성 인식 엔진을 사용하므로 autolinking이나 버전 불일치 문제가 원천적으로 없다.

### 구현 내용

**`android/.../SpeechRecognitionModule.kt` (신규)**

- `NativeSpeechRecognition` 이름으로 등록
- `startListening()`: RECORD_AUDIO 권한 확인 후 `SpeechRecognizer` 직접 생성, 한국어(`ko-KR`) 설정
- `DeviceEventEmitter`로 JS에 이벤트 전달: `speechResult` (텍스트), `speechError` (에러코드)
- Main Thread에서 SpeechRecognizer 조작 (`Handler(Looper.getMainLooper())`)

**`android/.../SpeechRecognitionPackage.kt` (신규)**

- `ReactPackage` 구현체, `SpeechRecognitionModule`을 패키지에 등록

**`android/.../MainApplication.kt` (수정)**

```kotlin
// 변경 전
PackageList(this).packages.apply { /* 비어 있음 */ }
// 변경 후

```

**`src/features/speech/ExpoSpeechAdapter.ts` (전면 재작성)**

- `PermissionsAndroid.request(RECORD_AUDIO)` 런타임 권한 처리
- `speechError` 에러 코드를 한국어 메시지로 변환

**`app.json` (수정)**

- `expo-speech-recognition` 플러그인 블록 제거

### 기술적 의사결정

| 대안 | 채택 여부 | 이유 |
|---|---|---|
| expo-speech-recognition 소스 패치 | ❌ | node_modules 수정은 유지보수 불가 |
| @react-native-voice/voice | ❌ | 또 다른 외부 모듈 — 동일 문제 재발 가능 |
