# 2026-08-05 개발일지

## 오늘의 요약

삼성 갤럭시 A34와 Android 에뮬레이터에서 앱이 스플래시 화면 이후 즉시 종료되는 크래시를 완전히 해결했다. 원인은 `expo-location` 패키지를 SDK 57용 버전(`57.0.7`)으로 잘못 설치한 것이었다. 우리 앱은 expo SDK 54를 사용하는데, 57.x 버전의 패키지 안에 사전 컴파일된 AAR 파일이 SDK 57에서 추가된 `AnyTypeCache` 클래스를 참조하고 있어 런타임에 클래스를 찾지 못하는 오류가 발생했다. SDK 54 공식 호환 버전인 `19.0.8`로 다운그레이드하자 문제가 해결됐고, APK의 DEX 파일에서 `AnyTypeCache` 참조가 완전히 사라졌음을 이진 분석으로 확인했다.

## 세션: ai-myeoneuri — `ClassNotFoundException: AnyTypeCache` 크래시 근본 원인 규명 및 수정

### 요청과 목표

- Samsung Galaxy A34 및 Android 에뮬레이터에서 앱이 스플래시 후 즉사 (`java.lang.ClassNotFoundException: expo.modules.kotlin.types.AnyTypeCache`)
- 이전 세션에서 원인을 `expo-location 57.x`의 pre-compiled AAR 버전 불일치로 완전히 특정
- 이번 세션 목표: 수정 구현 → 빌드 → 에뮬레이터 검증 → 진단 코드 제거 → 커밋

### 구현 및 변경 내용

**핵심 수정: expo-location 버전 다운그레이드**

- `package.json`: `"expo-location": "^57.0.7"` → `"~19.0.8"`
- expo SDK 54의 `bundledNativeModules.json`에서 공식 호환 버전이 `~19.0.8`임을 확인
- `npm install expo-location@~19.0.8 --legacy-peer-deps` 실행

**Gradle 설정 정리 (`android/gradle.properties`)**

- `reactNativeArchitectures`: `armeabi-v7a,arm64-v8a,x86,x86_64` → `arm64-v8a,x86_64` (불필요한 아키텍처 제거)
- `newArchEnabled`: `true` → `false` (이전 세션에서 New Architecture 비활성화)
- `expo.useLegacyPackaging`: `false` → `true`

**진단 코드 제거 (원래 상태 복원)**

- `app/_layout.tsx`: 에러 오버레이 UI 제거, 원래 Stack 네비게이터로 복원 (`bf7a583` 기준)
- `app/index.tsx`: `ErrorUtils.setGlobalHandler` 진단 핸들러 제거, 원래 AI 어시스턴트 화면 복원
- `index.js`: 진단용 커스텀 엔트리포인트 삭제
- `package.json` `"main"`: `"index.js"` → `"expo-router/entry"` 복원

### 문제와 해결 과정

**원인 특정 과정 (이전 세션에서 완료)**

1. `adb logcat`에서 `ClassNotFoundException: expo.modules.kotlin.types.AnyTypeCache` 확인
2. `expo-location`의 `expo-module.config.json`에서 `"publication"` 필드 발견 → pre-compiled AAR 사용 경로 확인
3. `expo-location/local-maven-repo/expo.modules.location-57.0.7.aar`를 JAR 해제하여 `LocationLastKnownOptions$__Pika.class` 등 Pika KSP 생성 클래스 확인
4. `dexdump -d`로 최종 APK DEX에서 `AnyTypeCache.INSTANCE.getTypesMap()` 바이트코드 참조 확인
5. `expo-modules-core 3.0.30`에는 `AnyTypeProvider`가 있고 `AnyTypeCache`가 없음 → 버전 불일치 확정

**해결 방법 선택**

- **Option A (채택): expo-location 다운그레이드** — `expo/bundledNativeModules.json`에서 SDK 54 공식 버전 `~19.0.8` 확인 후 변경
- Option B (미채택): `forceBuildFromSource` + KSP 플러그인 추가 — 소스에서 빌드 강제, 더 복잡하고 빌드 시간 증가

**expo-location 19.x 안전성 검증**

```
jar xf expo.modules.location-19.0.8.aar
jar tf classes.jar | grep -i "Pika\|AnyType"
# 결과: 출력 없음 (Pika KSP 클래스 없음)
```

- `expo-location 19.x`는 `@OptimizedRecord`/Pika KSP를 사용하지 않음 → `AnyTypeCache` 참조 없음

### 기술적 의사결정

**왜 `^57.0.7`이 설치됐는가**

`^` (caret) 지정자는 major 버전을 고정하지 않는다. expo 생태계의 패키지들은 SDK 버전과 major 버전이 일치하는 경우가 많아 (`expo SDK 54 → expo-location 19.x`, `expo SDK 57 → expo-location 57.x`), `^`를 쓰면 SDK 버전을 훌쩍 넘는 major 버전으로 업그레이드될 수 있다. expo 패키지는 반드시 `~` (tilde, 패치 범위) 또는 `expo install` 명령으로 설치해야 한다. `expo install`은 `bundledNativeModules.json`에서 SDK에 맞는 버전을 자동 선택한다.

**pre-compiled AAR 시스템의 위험성**

expo-location 57.x는 npm 패키지 안에 사전 컴파일된 AAR을 포함하고 있다. 이 AAR은 배포 시점의 expo-modules-core 버전에 맞게 컴파일됐는데, 앱이 다른 버전의 expo-modules-core를 사용하면 런타임에 클래스를 찾지 못한다. 에러 메시지가 `expo-location`이 아닌 내부 클래스명(`AnyTypeCache`)으로 나타나기 때문에 진단이 어렵다.

## 세션: APK 배포 시도 — Drive/GitHub Releases (미완)

### 요청과 목표

USB 없이 폰에 APK를 설치하기 위해 Google Drive 또는 GitHub Releases로 배포 시도.

### 시도 및 실패 과정

**Google Drive MCP 업로드 시도 → 불가**
- APK 27MB → base64 인코딩 시 37MB 문자열 생성
- MCP tool call parameter 크기 제한 초과 → 직접 업로드 불가

**GitHub Releases (`gh` CLI) → 미설치**
- `gh` CLI가 설치되어 있지 않아 사용 불가

**GitHub PAT + API 직접 호출 시도**
- Fine-grained PAT 발급 (`github_pat_11A2TBSW...`) → Releases 생성 권한 없음 (403)
- Classic PAT 재발급 시도 전에 사용자가 Google Drive 수동 업로드로 해결

**결과**
- 사용자가 Windows 파일 탐색기에서 직접 Google Drive에 APK를 올리고 폰에서 다운로드·설치
- 갤럭시 A34에서 앱 실행 확인 ✅

### 미해결 사항

- GitHub Releases 자동화 배포 미구축 (매번 수동 Drive 업로드 필요)
- `gh` CLI 설치 또는 Classic PAT 발급 시 자동화 가능
