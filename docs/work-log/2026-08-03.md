## 세션: Day 42 — 실기기 테스트 피드백 반영 UI 수정

### 요청과 목표

폰 실기기 테스트 후 발견된 9가지 문제 중 코드로 해결 가능한 항목들을 수정.

### 구현 및 변경 내용

**1. 랜딩 페이지 모바일 간격 개선 (landing-client.tsx)**

- Hero, Value Props, Comparison, CTA 섹션 모두 `padding: "80px 0"` 인라인 스타일 → `className="py-10 md:py-20"` 전환
- 모바일에서 40px(py-10), 데스크탑에서 80px(py-20) 적용
- CTA 섹션 `padding: "80px 24px"` → `className="py-10 md:py-20 px-6"`

**2. 비교표 텍스트 수직 적층 문제 해결 (landing-client.tsx)**

- 문제: 바깥 div의 `overflow: hidden`이 내부 `overflow-x-auto`의 스크롤을 막음 → 열이 좁아지면 한글이 글자 단위로 줄바꿈됨
- 해결: `overflow: "hidden"` → `overflow: "clip"` 변경 (시각적 클리핑은 유지하면서 내부 스크롤 허용)
- 테이블에 `minWidth: 460` 추가해 자연스러운 수평 스크롤 유도
- 모든 `<th>` 셀에 `whiteSpace: "nowrap"` 추가
- "Google Recorder" → "Google Rec." 축약 (20% 열에서 줄바꿈 방지)

**3. AI 비서 입력 폼 다크모드 강제 색상 수정 (care-assistant-panel.tsx)**

- 원인: 앱 자체는 라이트 모드이지만 Android Chrome이 네이티브 폼 요소(select, textarea)에 자동 다크 테마를 적용
- 해결: `colorScheme: 'light'` + 명시적 `backgroundColor: '#f8fafc'`, `color: '#101828'` 인라인 스타일 추가
- Tailwind 클래스 `bg-slate-50 text-slate-800`은 Android Chrome의 네이티브 다크 오버라이드를 막지 못해 인라인 스타일로 전환
- textarea·버튼 패딩 `py-3` → `py-2`로 줄여 입력창 높이 감소
- 버튼 `px-6 text-base` → `px-5 text-sm` 슬림화

**4. 어르신 탭 등록 폼 팝업 전환 (parents-client.tsx)**

- 기존: 페이지 하단에 `ParentProfileForm` 인라인 노출
- 변경: 상단 헤더 영역에 "어르신 등록 +" 버튼 추가, 클릭 시 모달 오버레이로 표시
- 수정 모달과 동일한 구조 재사용 (`fixed inset-0 z-50 bg-black/50`)
- 등록 완료 후 모달 닫히고 1.2초 후 대시보드로 이동 (기존 동작 유지)

**5. 화면 전환 스피너 가시성·최소 노출 시간 개선 (navigation-progress.tsx)**

- 문제 1: `bg-white/90` 클래스가 다크 모드에서 `.dark .bg-white → #1e293b`로 재매핑되어 스피너 원이 다크 배경에 묻힘
- 해결: 인라인 스타일 `rgba(255,255,255,0.95)`로 고정해 다크모드 재매핑 방지
- 스피너 테두리도 `border-slate-200 border-t-blue-500` → 인라인 스타일로 전환
- 문제 2: Next.js App Router 페이지 전환이 너무 빨라 스피너가 순간 깜빡이고 사라짐 → 애니메이션이 없어 보임
- 해결: `MIN_SHOW_MS = 350` 도입, 페이지가 빠르게 로드돼도 최소 350ms는 스피너 유지
- `loadStartRef`로 클릭 시각을 기록, pathname 변경 시 경과 시간을 계산해 나머지 delay 부여

**6. 전체 리포트 생성 → CSV 다운로드 자동 연결 (caseworker-client.tsx)**

- 문제: "전체 리포트 생성" 클릭 시 "생성 완료 ✓"만 표시되고 다운로드가 없었음
- `/api/reports/batch` 응답에서 `reportSetId`를 수신해 state로 저장
- 생성 완료 후 버튼이 "✓ 생성 완료" + "CSV 받기" 링크로 교체됨
- "CSV 받기" 클릭 시 해당 `reportSetId`로 필터된 CSV 다운로드, 이후 버튼 초기화

### 기술적 의사결정

**Android Chrome 강제 다크모드 vs Tailwind 클래스**

Tailwind의 `bg-slate-50`는 `class="dark"` 선택자 기반 앱 내 다크모드에만 반응한다. Android Chrome의 `forced-dark-mode`는 네이티브 form 렌더링 단계에서 OS 레벨로 적용되어 CSS 클래스를 우선하지 않는다. `color-scheme: light` 선언이 이 레이어를 제어하는 공식 방법이다.

**overflow: clip vs overflow: hidden**

`overflow: hidden`은 스크롤 컨테이너를 생성해 내부 요소도 스크롤 불가로 만든다. `overflow: clip`은 시각적 클리핑만 하고 스크롤 컨텍스트를 생성하지 않아 내부 `overflow-x: auto`가 독립적으로 동작한다. 모서리 둥글기(border-radius)를 유지하면서 가로 스크롤을 허용할 때 적합하다.

**스피너 최소 표시 시간**

Next.js 15+ App Router는 클라이언트 컴포넌트를 미리 캐시해 페이지 전환이 100ms 미만으로 빨리 끝날 수 있다. 사용자가 "뭔가 돌고 있다"고 인식하려면 최소 300ms 이상 애니메이션이 보여야 한다. 350ms를 기준으로 설정했다.
