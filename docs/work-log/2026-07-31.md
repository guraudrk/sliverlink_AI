웹 앱(PWA)에서 사용자가 직접 크롬으로 확인한 UX 문제 6가지를 두 세션에 나눠 수정했다. 1차 세션: 하단 탭 "부모님" → "어르신" 변경, 어르신 카드에 삭제 버튼 추가, AI 보고서 캐싱(재클릭 시 즉시 표시). 2차 세션: AI 보고서 타이핑 이펙트를 버퍼+인터벌 방식으로 전면 교체해 촤르륵 자연스럽게 문자가 흐르도록 개선, 헤더 높이 고정(이름 길이와 무관하게 항상 동일한 높이), 메인 화면 어르신 카드 클릭 → 사회연결점수·최근통화·안전알림·일정·AI 보고서 버튼이 담긴 팝업 추가, 화면 전환 스피너를 화면 정중앙으로 이동.

### 구현 및 변경 내용

**탭 명칭 변경**
- `mobile-bottom-nav.tsx`의 `/parents` 탭 label을 `"부모님"` → `"어르신"`으로 수정

**삭제 버튼**
- `parent-profiles-repo.ts`에 `deleteParentProfile` 함수 추가: RLS가 `owner_user_id` 기준으로 타인 행 삭제를 막으므로 소유권 검증은 별도로 하지 않음
- `parent-profile-list.tsx`에 `onDelete?: (id: string) => void` prop 추가, 카드 좌상단에 X 버튼 배치. 클릭 시 `window.confirm`으로 확인 후 삭제, 이벤트 버블링 차단(`stopPropagation`)

**AI 보고서 캐싱**

- 스트리밍 완료 후 `onGenerated(fullText)` 호출 → 부모에서 캐시 갱신

**스트리밍 커서 애니메이션**
- `care-report-panel.tsx`에 `streaming` boolean 상태 추가: 응답 스트림 읽기 시작 시 `true`, 완료/에러 시 `false`
- `globals.css`에 `@keyframes cursor-blink` + `.animate-cursor-blink` 클래스 추가 (0.8초 step-end 반복)
- 텍스트 렌더링 영역에서 `streaming === true`일 때 teal 색상 커서(`<span>`) 표시

### 문제와 해결 과정

- 삭제 후 서버 재로드 없이 화면 갱신: `deleteParentProfile` 호출 성공 후 클라이언트 `profiles` 상태를 filter로 즉시 갱신해 해결. 실패 시 에러가 throw되므로 상태는 변경되지 않음 (에러 핸들링 토스트는 이번 범위 밖으로 보류)
- `initialText`가 있으면 `useEffect`의 `generate()` 호출을 건너뛰어야 함: `useEffect` 의존성 배열에 `initialText`를 추가하고 초기 렌더링에서 `if (initialText) return`으로 단락

### 기술적 의사결정

- **삭제 API 라우트 대신 브라우저 Supabase 클라이언트 직접 사용**: 이미 같은 패턴(`alert-banner.tsx`, `web-recorder.tsx` 등)이 코드베이스 전반에 사용 중. 별도 API Route 파일을 만들면 파일 수만 늘어나고 RLS가 이미 소유권을 보장함
- **캐시를 `Map`이 아닌 `Record<string, string>`으로**: React 상태로 관리하므로 직렬화 가능한 일반 객체가 더 안전. 세션 간 캐시를 유지할 필요 없으므로 localStorage 미사용
- **`window.confirm`으로 삭제 확인**: 별도 확인 다이얼로그 컴포넌트를 만드는 것은 범위 초과. 브라우저 내장 confirm이 가장 단순

## 세션: 타이핑 이펙트·헤더 고정·어르신 팝업·중앙 스피너

### 요청과 목표

첫 번째 세션에서 수정했다고 했지만 실제로는 여전히 잘못된 항목들을 재수정했다.
- **#1**: 스트리밍 타이핑 이펙트가 여전히 덩어리째 텍스트가 나오는 문제
- **#2**: 상단 헤더 높이가 이름 길이나 줄바꿈에 따라 바뀌는 문제
- **#5**: 메인 화면 어르신 카드 클릭 시 팝업 미구현
- **#6**: 화면 전환 스피너가 화면 중앙이 아닌 구석에 표시

### 구현 및 변경 내용

**#1 타이핑 이펙트 전면 교체**

기존 방식: `setText(prev + chunk)` → API가 보내는 청크 크기대로 텍스트가 덩어리 단위로 뭉쳐서 나타남.

새 방식: `bufferRef`(API 수신 버퍼, ref) + `displayIdxRef`(현재 표시 위치) + `setInterval`(16ms 주기).
- API가 보내는 청크와 무관하게 항상 16ms마다 12자씩 `displayText`를 전진
- 타이핑 중에는 plain text + teal 색상 깜박이는 커서(`animate-cursor-blink`)
- 타이핑 완료 후 `<MarkdownContent>`로 전환(마크다운 렌더링)
- 스크롤이 타이핑 중 자동으로 최하단으로 이동

`bufferRef`를 state 대신 ref로 쓴 이유: API 청크를 받을 때마다 `setState`를 호출하면 16ms 인터벌과 충돌해 불필요한 리렌더링이 생김. ref에 축적해두고 인터벌이 읽어가는 구조가 더 안정적.

**#2 헤더 높이 고정**

`paddingBottom: 32` 방식은 내용에 따라 실제 높이가 달라짐.
`minHeight: 160` + `pt-10 pb-10` 고정 패딩으로 교체. 이름 길이와 무관하게 동일한 높이 보장.
`<br />`도 제거해 줄바꿈 변동 제거.

**#5 어르신 카드 팝업**

`dashboard/page.tsx`(Server Component)의 어르신 그리드를 `DashboardEldersSection`(Client Component)으로 분리.
카드 클릭 → `ElderQuickPopup` 모달 오픈 → Supabase 브라우저 클라이언트로 다음 4개 병렬 쿼리:
- `social_scores`: 최신 1건 점수 (양호/보통/주의 라벨 + 색상)
- `call_recordings`: 최신 통화일 (`recorded_at`, 상대 시간 포맷)
- `safety_alerts`: 미확인 건수 (`acknowledged_at IS NULL AND elder_id = ?`)
- `care_tasks`: 완료 안 된 일정 3건

팝업에서 "AI 케어 보고서" 버튼 클릭 시 `CareReportPanel`을 overlay로 표시. 보고서 캐시는 `DashboardEldersSection` 상태로 관리해 팝업 닫고 다시 열어도 캐시 유지.

Empty state(어르신 0명)도 `DashboardEldersSection` 내부에서 처리.

**#6 스피너 중앙 이동**

`fixed bottom-[4.5rem] right-4 sm:top-[3.75rem]` → `fixed inset-0 flex items-center justify-center`.
`backdrop-blur-sm` 추가로 배경이 살짝 블러되어 로딩 중임을 직관적으로 전달. 크기도 h-9 → h-14로 키움.

### 문제와 해결 과정

- `ParentProfile.relationship`이 `string | undefined`(optional)인데 컴포넌트 prop 타입을 `string | null`로 선언해 타입 에러 발생. `?` optional로 수정 후 해결.

### 기술적 의사결정

- **팝업 데이터 패치를 클릭 시점으로**: 대시보드 Server Component에서 모든 어르신 데이터를 미리 fetch하면 응답 느려짐. 클릭 시에만 해당 어르신 데이터를 패치하는 lazy 방식이 더 적합.
- **`elder_id` vs `parent_id`**: `safety_alerts` 테이블은 `elder_id`, `call_recordings`는 `parent_id`를 외래키로 사용. 팝업에서 각 테이블 컬럼명을 개별 지정.
