### 데모 환경 접근 방법 — 2026-08-12 실측 정정

> **정정:** "실제 데이터 없이 UI 전체 확인 가능"은 부정확합니다. `/demo`는 `(protected)` 그룹 안에 있어
> **로그인이 필수**입니다. `(protected)/layout.tsx`가 `redirect("/login")`을 겁니다.
> 실제 흐름은 아래와 같습니다.

```
영업자 계정으로 로그인
  → /demo  (데모 화면이 아니라 "데이터 생성 버튼" 페이지)
  → [어르신 30명 데모 데이터 생성] 클릭  (약 5초)
  → run_demo_seed RPC 실행
  → /dashboard/caseworker 자동 이동   ← 실제 시연은 여기서
```

생성되는 데이터: 즉시확인 5명 / 추세 악화 8명 / 정상 7명 / 보통 10명 = 30명.
데모 전용 기관으로 격리되고, RAG 인덱싱도 백그라운드로 함께 돕니다. **시연 설계는 잘 되어 있습니다.**

3분 시연 경로가 `/demo` 화면에 안내되어 있음: ① KPI 헤더 → ② 🔴 카드 플래그 사유 → ③ 보고서 생성 → ④ 기록 복사

### ⚠️ 시연 전 반드시 확인할 것 2가지

**1. `run_demo_seed` RPC가 DB에 실제로 존재하는가**

`/api/demo/seed-org`가 이 함수를 호출합니다. 없으면 미팅 중 버튼을 눌렀을 때 500이 뜹니다.
Supabase SQL 에디터에서 확인:

```sql
SELECT proname FROM pg_proc WHERE proname = 'run_demo_seed';
```

**2. 로그인 화면 카피가 B2C 문구다 — 기관 미팅에서 첫 화면이다**

화면 공유를 켜면 기관 담당자가 제일 먼저 보는 화면입니다. 현재 문구는 전부 개인 대상입니다.

| 위치 | 현재 | 교체안 |
|---|---|---|
| `(auth)/login` 제목 | 다시 만나서 반가워요 | 통화 기록을 이어서 관리하세요 |
| 부제 | 로그인하고 **부모님 돌봄**을 이어가요 | 기관·가족 계정으로 로그인해 주세요 |
| 폼 안내 | **자녀·보호자** 계정으로 로그인해 주세요 | (삭제 — 부제와 중복) |
| `app/layout.tsx` metadata description | **가족이** 어르신과 나눈 통화를 AI가 분석해 건강 신호를 기록하는 SilverLink AI | **생활지원사가** 어르신과 나눈 통화를 AI가 정리해 기록으로 만드는 SilverLink AI |

2026-08-10에 랜딩 기본 탭은 기관으로 바꿨지만 로그인 화면과 메타 설명은 그대로 남아 있습니다.

| | 네이버 클로바 케어콜 | SilverLink |

### 영업 채널 순서 — 이메일 우선으로 변경 (2026-08-12 확정)

> 이전 브리핑은 "전화 우선"이었으나 **이메일 우선으로 확정**되었습니다.
> 사유: 줄글본·후속 2회·발송 운영까지 완성되어 있고, 개발·면접과 병행 가능합니다.

1. **콜드메일 발송** — 화·수·목 오후 2~4시, 하루 최대 15통
   (요양기관은 오전에 안부 전화가 몰려 가장 바쁨)
2. **후속 메일** — 5일 뒤 1회, 2주 뒤 마지막 1회. **3차는 보내지 않음**
3. **시연 예약** — "15분만 화면 공유로 보여드릴게요"
4. **시연 당일 팔로업 메일** — 본 것 요약 + 가격 + 다음 스텝
5. **파일럿 계약** — 첫 3개월 무료, 이후 정가 전환

**기대 회신율은 5% 안팎입니다.** (2026년 B2B 콜드메일 평균 3.4%, 50통 미만 소량 발송 평균 5.8%)
46곳 발송 → 회신 2~4곳 → 미팅 1~2곳 → 파일럿 0~1곳이 현실적인 숫자입니다.

> 회신율을 가르는 것은 발송량이 아니라 **기관별 맞춤 문단**입니다.
> 강남 노인통합지원센터에만 홈페이지에서 확인한 사실("주 1회 방문, 주 2회 전화")을 넣었고

- 접근 제어: 기관별 RLS, 타 기관 데이터 열람 불가

### 아직 미구현 — 계약 전 선결 필요

- **어르신 본인 동의 획득 절차**: 제품 내 동의 흐름이 없음. 기관이 자체 동의서를 받는 방식으로 우선 운영.
- 미구현 사실을 제안서에서 숨기지 말 것. "기관이 자체 동의서 운영 → 향후 앱 내 동의 흐름 제공 예정"으로 투명하게 명시.

### 법적 근거

- 통신비밀보호법 상 **본인 동의** 또는 **상대방 동의** 중 하나만 있으면 녹음 가능
- 생활지원사(통화자)가 사전에 고지하고 통화하는 방식으로 합법적 운영 가능
- 기관 계약 시 이 사실을 안내하는 문구를 계약서에 포함 권장

## 8. 현재 두 제품 포지션 요약

| | SilverLink | AI 며느리 |
|---|---|---|
| 타겟 | 방문요양·주간보호(A) + 노인맞춤돌봄(B) | 어르신 직접 사용 |
| 수익 모델 | B2B 기관 구독 (15/30만원·3천원, 첫 3개월 무료) | 미정 (현재 무료, 결제 미구현) |
| 우선순위 | **1순위 — 지금 영업 개시** | 2순위 — SilverLink 매출 확보 후 |
| 희소성 | 높음 (국내 통화 분석 SaaS 없음) | 중간 (시니어 케어 앱 다수 존재) |

### 왜 SilverLink가 먼저인가 (2026-08-12 판단)

| | SilverLink | AI 며느리 |
|---|---|---|
| 영업 자료 | 제안서·콜드메일·리드 46곳 **완성** | 없음 |
| 결제 수단 | 계좌이체·세금계산서 (B2B 관행) | **미구현** |
| 유통 | 이메일 발송이면 끝 | 스토어 심사 + 마케팅 |
| 객단가 | 월 15만원 | 월 9,900원 가정 시 약 15배 차이 |
| 목표 도달 | 20곳 | 300가구 |

SilverLink는 **막힌 것이 영업 하나뿐**입니다. 며느리는 돈 받을 방법 자체가 아직 없습니다.

**다만 며느리를 접는 것이 아닙니다.** 지금 며느리의 가치는 자체 매출이 아니라 **기관 미팅에서의 차별화**입니다.
경쟁사(KT 다솜이·ChinguAI·미스터마인드)는 전부 기기·로봇을 놓는 방식이라,
"복지사용 시스템과 어르신이 직접 쓰는 앱을 함께 만든다"는 문장이 실제로 다르게 들립니다.
**며느리는 데모에 붙이고, 돈은 SilverLink에서 먼저 받습니다.**
